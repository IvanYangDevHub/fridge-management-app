# Domain Docs

This is a single-context repository.

Before working on a domain area, read root `GLOSSARY.md` if present and relevant ADRs under `docs/adr/` if present. Proceed when they do not exist; create them only when terms or decisions need recording.

Use glossary terms consistently in issues, specs, code, and tests. If a proposed change conflicts with an ADR, identify the conflict rather than silently replacing the decision.
